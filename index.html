GitHub Actions YAML Builder

Build a GitHub Actions workflow file without digging through the docs. Tick a box to add that field to your workflow. Each layer lists every field allowed at that spot, in the same order as GitHub's docs. Ticked fields that still need a value turn orange.

    
      
    
      
    Covers the common fields of the workflow syntax reference. Your work is saved in this browser.
    
    
    
  
    

  
    
    
    
      
    How to make a GitHub Actions workflow here
    
      
      
        
    1. Under on, tick the events that should start the workflow, such as push, pull_request or schedule.
      2. 
        
    2. Under jobs, add a job, pick a runner in runs-on, and add steps. Each step either uses an action like actions/checkout or runs shell commands.
      3. 
        
    3. Turn on extras when you need them: a strategy.matrix to test several versions, permissions for the GITHUB_TOKEN, concurrency to cancel old runs, or services for a database.
      4. 
        
    4. Fix anything listed in orange, then press Copy or Download and save the file in .github/workflows/ in your repository.
      5. 
        
    5. Already have a workflow? Use Import YAML to load it, or Share link to send yours to someone.
      6. 
      
    
    
    
    
    
      
    FAQ
    
      
    
        
    Where do I put the generated workflow file?
    
        
    Save it in your repository under .github/workflows/ with a .yml or .yaml extension, for example .github/workflows/ci.yml. GitHub picks it up on the next push.
    
        
    Does the builder upload my workflow anywhere?
    
        
    No. Everything runs in your browser and your work is saved only in your browser's local storage. A share link holds the workflow inside the link itself, so nothing is stored on a server.
    
        
    Which workflow fields are supported?
    
        
    The common ones: name, run-name, on (push, pull_request, workflow_dispatch, workflow_call, schedule, workflow_run, release, issues and more), permissions, env, defaults, concurrency, and jobs with runs-on, needs, if, strategy matrix with include and exclude, environment, container, services, outputs, steps, uses and run.
    
        
    Why are some fields orange?
    
        
    A ticked field needs a value. Orange fields are listed in the to-do box above the YAML; click one to jump to it.
